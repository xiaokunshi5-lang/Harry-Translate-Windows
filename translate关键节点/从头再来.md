## 第一部分：本地三个项目逐个深度解析（基于 `README.md`）

### 1.1 最初版：[`../README.md`](../README.md)

- **文档标题与版本**：《会议实时双向双屏同传系统（最初版 · 纯双通道）》（无版本号）。
- **核心用途与定位**：极简双通道会议实时同传与多屏浏览器投屏系统，服务线下或小型会议场景：
  - `/en`：中译英大屏（面向外宾全屏投屏，英文自动直出）。
  - `/zh`：英译中大屏（面向中方全屏投屏，中文自动直出）。
  - `/split`：左右双栏监看屏（主控电脑同屏对照监看两路输出）。
  - `/`：主控导航首页。
  - 文档明确界定**不包含悬浮窗、术语库、多引擎切换等复杂扩展**。
- **已完成功能**：
  1. 中英双向独立浏览器大屏与双栏监看屏。
  2. 双通道异步解耦（单路重连不影响另一路正常翻译）。
  3. `/api/stats` 实时展示输入/输出 Token 消耗及预估费用。
  4. 跨平台启动与密钥替换脚本（macOS `启动同传系统.command`、`./start.sh`、`切换API_Key.command`；Windows `.venv` + `python server.py`；通用 `python switch_key.py` 与 `.env`）。
- **技术路径**：阿里云百炼千问实时同传大模型（`qwen3.8-livetranslate-flash-realtime`）+ Python（`server.py`）+ `FastAPI` + `WebSocket`，前端为纯浏览器网页。
- **实现同传的方式**：
  - **音频采集**：单麦克风拾音（未涉及会议系统内录、微切片参数、AGC 或自定义 VAD 调优）。
  - **缓冲推流**：麦克风采样与云端 WebSocket 推流队列按方向异步隔离。
  - **推理与展示**：中译英、英译中双路并发直连 DashScope 实时同传模型，由 FastAPI 通过 WebSocket 推流至浏览器页面。
- **整体架构**：
  ```text
  单麦克风拾音
     ├──▶ 异步队列 A（中译英）──▶ Qwen 3.8 WebSocket ──┐
     └──▶ 异步队列 B（英译中）──▶ Qwen 3.8 WebSocket ──┼──▶ FastAPI / WebSocket 服务 ──▶ 浏览器视图（/, /en, /zh, /split）+ /api/stats
  ```

- **文档标题与版本**：《Harry Translate (哈利同传)》，正式旗舰版 **`Release-v4.0.0`**（公开基线 `v3.6.0 -> v3.8.0 -> v3.9.0 -> v3.9.1 -> v4.0.0`，对应公开仓库 [`xiaokunshi5-lang/harry-translate`](https://github.com/xiaokunshi5-lang/harry-translate)，已核验为 `Apache-2.0`，`v4.0.0` 发布与最近提交均为 `2026-11-07`，截至 `2026-11-19` 为 `0 stars`）。

     - 增加双阶微停顿合并：`<= 300ms` 合并至同段，`> 450ms` 保持视觉焦点不黑屏闪烁。
  4. **远场自适应软限幅 AGC + 240ms Server VAD + WebKit 直写**：
     - 50ms 热路径内嵌 **`2.3µs`（`0.0023ms`）C 级自适应软限幅 AGC**（`noise_floor = 240.0`，向 `target_rms = 1200.0` 最高提振 `3.2x`，`tanh` 曲线在 `±31500` 软限幅防近身爆音），专门应对 1~2 米会议桌远场拾音。

     - 动态增量更新云端热词帧严格限幅 **`<= 48` 词（`< 2.5KB` UTF-8）**防止大模型 Attention 预填充拖慢音频上行，全量建连仍维持 `<= 900` 词安全线。

## 第三部分：`yuxino/Mimi` 深度剖析与逐项对比

- **项目地址**：[`https://github.com/yuxino/Mimi`](https://github.com/yuxino/Mimi)（主页 `https://mimi.yuxino.cn`）
- **仓库状态（截至 2026-11-19）**：**920 stars / 57 forks** · **MIT 协议** · 创建于 `2026-07-22` · 最新主干提交 `c134bd3`（`2026-11-19`）· 最新 Release **`v1.7.4`**（`2026-11-18`，11 月 13 日至 18 日连续发布 `v1.7.0 -> v1.7.4`）。
- **定位**：面向**个人看外语视频、直播、网课**的跨平台（macOS / Windows / Linux / Android）开源实时字幕与翻译桌面/移动应用。

### 3.1 技术架构与核心能力
1. **跨端架构**：**Tauri v2**（`wry`、`tray-icon`、`macos-private-api`）+ **Rust（1.90）共享核心**（`shared/mimi-core` 纯状态机与字幕对齐、`shared/mimi-runtime` 协议客户端/管线、`shared/mimi-android-jni`）+ **React 19.2 / TypeScript 5.9 / Zustand 5.0 / Tailwind CSS 3.4** + macOS Swift 端侧桥接。
2. **免 BlackHole 原生音频采集与回声消除**：
   - **macOS**：14.2+ 默认走 Core Audio Process Tap（`AudioHardwareCreateProcessTap` / `CATapDescription`，无需屏幕录制权限，仅弹窗请求 System Audio Recording Only），macOS 13–14.1 或单应用抓取走 `ScreenCaptureKit`（`SCStream`）。
   - **Windows**：`cpal 0.18`（含 `AUDCLNT_BUFFERFLAGS_SILENT` 补丁）WASAPI loopback + Win11 build 20348+ 单应用进程环回。
   - **Linux**：`libpulse-binding` 抓取默认输出或单个播放流。
   - **重采样与 AEC**：`rubato 5` FFT 重采样（`RESAMPLE_CHUNK_FRAMES = 1024`）至 16/24kHz；当选择 `Both`（系统+麦）时启用 **SpeexDSP**（`aec-rs-sys = "=1.0.0"`，500ms 滤波器，关闭非线性预处理）消除外放回声，但两路音频仍各自维持独立的 `AudioSendPipeline`（`QUEUE_CAPACITY = 20`）与上游连接。
3. **12+ 实时/文本翻译路线**：支持 `AlibabaCloud`（`qwen3.8/3.5-livetranslate-flash-realtime` 或 Audio3）、`OpenAIRealtime`、`GoogleGeminiLive`、`AzureOpenAIRealtime`、`VolcanoEngine`（豆包同传 2.0）、`TencentCloud`、`BaiduTranslate`、`XAIRealtime`、`AppleSpeech` / `Apple Translation`（macOS 26+ Apple Silicon 端侧）、`DeepL`、`DeepLX` 及 13 个 OpenAI 兼容预设（含 Ollama / LM Studio）；独立文本翻译器走 `HighQualityTranslationClient`（可替换的预览泳道 + 45s 超时保障的串行定稿队列）。
4. **工程细节**：JSON 持久化配置（密钥明文存于私有 `credentials/credentials.json`）、支持 TXT/Markdown/WAV 导出与内置播放器、集成 `tauri-plugin-updater`（但 `docs/usage.md` 明确说明 macOS DMG 仅自签名未公证、Windows 安装包为未签名预览版）。

### 3.2 悬浮屏透明、交互与体验优势
1. **可控纯色透明与无底沉浸态**：不依赖 `backdrop-filter: blur()` 也不使用 `NSVisualEffectView`/Acrylic，常规态用 `rgba(0,0,0, opacity/100)`（0–100% 滑块，默认 80%）使背景透明度绝不连带拉低字幕字迹清晰度；沉浸态直接纯透明背景 + 多层 `IMMERSIVE_TEXT_SHADOW`（高对比描边阴影）。
2. **跨平台非激活与全屏 Space 随行**：
   - macOS 将 `overlay` 与独立控制子窗 `overlay-control` 转为 `NSPanel`（`NonactivatingPanel` + `NSScreenSaverWindowLevel` + `CanJoinAllSpaces | Stationary | IgnoresCycle | CanJoinAllApplications | FullScreenAuxiliary`），通过 `orderFrontRegardless()` 压在原生全屏视频之上且不抢输入焦点；监听 `NSWorkspaceActiveSpaceDidChangeNotification`（250ms 防抖）跨 Space 随行并分离运行时 `presentation_frame` 与持久 `user_frame`。
   - Windows 用 `focusable(false)` + 150ms `WindowsWorkspaceFollower`（COM `IVirtualDesktopManager`）+ 混合 DPI 逻辑尺寸补偿。
   - Linux Wayland 自动将 `overlay-control` 内嵌回 `overlay` WebView 并用 Cairo 复合输入区域解决定位受限问题。
3. **真点击穿透 + 悬停解锁**：锁定或沉浸混融态开启 `set_ignore_cursor_events`（Linux 用空 Cairo Region）实现鼠标彻底穿透；靠 macOS `NSTrackingArea(ActiveAlways)` / Windows `80ms` `GetCursorPos` 轮询触发悬停状态，保留 `LockedLanguageStatusCapsule` 悬停解锁胶囊（出错时自动解除穿透方便点重试）。
4. **全画布拖拽、8 向缩放与折叠态**：
   - 在字幕画布任意非控件/滚动条区域按下即可调用 `performWindowDragWithEvent` 拖拽整窗（无需死盯左上角小把手）。
   - 8 向缩放边缘句柄通过 `screenX/Y` 直接提交屏幕坐标给 Rust 计算（`360–1200 × 100–600`），避免边缘拖拽反馈震荡。
   - 独立子窗 `overlay-control`（`156×30` 胶囊 <-> `280×132..520` 面板）与 `180ms` 缓动折叠态（`280×54` 迷你条，滚轮上滑即展开）。
5. **抗抖动排版**：`useSubtitleTail.ts` 分场景防抖（源文 `180ms/750ms`、流式译文 `100ms/250ms`、非流式 `400ms/1500ms`，仅空会话首句立即显示），`useRollupGlide` 为换行提供 `180ms ease-out` `translateY` 位移补偿，`TimelineScroll` 上翻回看自动锁住当前句 ID 并浮现 `"Return to live"`。

### 3.3 已核实的 `Mimi` 会议同传短板（源码确认缺失）
1. **无用户可配置热词/术语表/自定义 Prompt**：虽然底层 `live_translate.rs`（`L132–133, L171–172`）已实现非空 `hotwords` 到 `translation["corpus"]["phrases"]` 的序列化，但上游 `translation_client.rs`（`L164, L349`）始终硬编码传入空的 `BTreeMap::new()`；且 `qwen_mt.rs`（`L590, L724–749`）等处硬编码了**影视剧/电影台词提示词**（要求保留叹息、喘息、哭声等语气）和口语填充词表，设置界面没有任何词库/Prompt 入口。
2. **无本地离线术语匹配与 ASR 同音字纠偏**：不存在任何 Aho-Corasick、Trie 或确定性词典替换层。
3. **固定单例架构，无多屏投屏与双悬浮窗**：固定单一 `settings`、`overlay`、`overlay-control` 窗口及单一 `OverlayState`，没有 LAN Web 服务，无 `/en`/`/zh`/`/split` 投影端，也不支持 `--dual` 双向对称镜像分屏。
4. **无 Token 统计/限额与省流门控**：仅有请求节流器，无本地 Token/费用估算与上限保护，`Both` 模式直接开两路满载连接。
5. **无会议声学/断句精细控制**：无用户可调 VAD、AGC 与非线性降噪；`live_translate.rs` 强制要求北京 `workspace_id` URL、强制 `SourceLanguage::Automatic`，且未设置 `240ms` `server_vad` 或主动 `commit`。
6. **其他会议制约**：无说话人分离（仅区分 `system`/`microphone`）；单次会话仅支持单向翻译目标语；无语音输出（Discard `OutputAudio`）。

## 第四部分：两条技术路线七维度评估与基座裁决

- **路线 A**：以 **`阿里同声传译` (`v4.0.0`)** 为基座，借鉴并补入 `Mimi` 等项目的悬浮屏与采集能力。
- **路线 B**：迁移至 **`yuxino/Mimi`** 为基座，补回你已有的热词银行、会议双屏/双窗、远场 AGC 与流控体系。

### 4.1 七维度详细对比

1. **功能覆盖**：路线 A 已经拥有 100% 会议同传核心能力（18,449 词、Smart Cap、`#config-drawer`、`--dual` 对称与纯度锁、`/en`/`/zh`/`/split`、50% 省流），仅缺免 BlackHole 采集、真点击穿透、Space 随行与多厂商驱动；路线 B 在会议核心能力上几乎空白，必须重写全部热词、工作台、双窗与投屏模块。
2. **架构合理性**：路线 A 的**服务端中心化 Hub（FastAPI + WebSocket）**天然支持多端同源广播（桌面 HUD + 外宾投影 + 中方副屏 + 未来手机扫码端）；路线 B 的**客户端单体（Tauri 单例窗口 + IPC）**虽然跨端优雅，但为了实现 `--dual` 与 `/en`/`/zh`/`/split` 必须打破其单例状态不变量并外嵌 HTTP/WS 服务器。
3. **实时性**：路线 A 全链路为“极速首字”设计（`50ms` 切片、`2.3µs` AGC、`240ms` VAD + 主动 Commit、`0.0018ms` DOM 直写）；路线 B 为追求阅读顺滑加入了 `1024` 帧重采样、`20` 深度队列和 `100~250ms` 前端防抖，且其 DashScope 协议未启用 `240ms` VAD 与主动 Commit。
4. **可维护性**：路线 A 为 Python 单一后端 + 标准 Web 前端，316 项自动化测试覆盖高，唯需留意 `ctypes` FFI 无编译检查与 `.venv` 环境管理；路线 B 横跨 Rust + TS/React + Swift + Kotlin/JNI + Win32 五种技术栈，任何新功能都要穿透 5 层跨语言契约，维护门槛显著更高。
5. **扩展性**：路线 A 更适合向**会务多屏、私有企业术语接口、BYOD 旁听、后期外包薄桌面壳（Sidecar）**演进；路线 B 更适合向**个人 BYO-AI 多模型、Linux/Android 全端覆盖**演进。
6. **迁移/改造成本**：
   - **路线 A 增量升级（约 2–4 人周）**：新增一个 ~250 行 Swift `AudioHardwareCreateProcessTap` 辅助程序（1~1.5 周）+ 升级 `float_app.py` 的 `NSPanel` Space 随行/点击穿透/Windows Topmost 重申（1 周）+ 抽离多引擎接口（1 周），**对核心词库与会议链路零破坏**。
   - **路线 B 侵入式分叉（约 6–12 人周）**：解锁热词与提示词（1.5 周）+ 重写 Rust AC 自动机与工作台 UI（2 周）+ 打破单例推双窗镜像与内嵌 Web 投屏服务（2.5~4 周）+ 移植远场 AGC/240ms VAD/50% 省流（1.5~2 周），外加应对上游日更级迭代的长期合并负担。
7. **风险**：
   - 选路线 B 面临三大现实风险：① `Mimi` 的 Qwen 3.8 协议强绑北京 `workspace_id` 且限死 `SourceLanguage::Automatic`；② 跨平台 `Tauri` 并不自动消除苹果公证与权限弹窗（`Mimi` 自身仍为未公证 DMG 与未签名 Win 安装包，且 macOS Process Tap 仍会触发“仅系统音频录制”授权弹窗）；③ 非激活 `NSPanel` 的点击穿透一旦和顶栏悬停逻辑协调不好，会导致按钮无法点击锁死。
   - 选路线 A 的主要风险是 Python 环境安装门槛与 `ctypes` 层维护，前者可通过后续“薄桌面壳 + Python Sidecar”（`auto-caption` 模式）平滑化解。

### 4.2 基座选型结论与“保留 / 借鉴”清单
- **结论：强烈推荐路线 A（以 `阿里同声传译 v4.0.0` 为基座）**。你花费大量心血在行业深水区打磨出的壁垒（万级热词双轨截断、远场 AGC、240ms 断句、双窗纯度防火墙、多屏投屏），迁移到 `Mimi` 的成本与风险远高于把 `Mimi` 的浮窗与内录特性嫁接到你的现有基座上。
- *(仅当你的产品定位彻底放弃会议双屏/确定性热词，转型为“个人跨端看外语视频字幕工具”时，才应选用路线 B。)*
- **必须保留（你的核心护城河）**：
  1. `50ms` 零拷贝切片 + `2.3µs` 远场软限幅 AGC + `240ms` Server VAD + 主动 Commit 断句策略；
  2. `18,449` 词 `glossary_bank/` + `P0~P3` 分级与 `<=48`/`<=900` Smart Cap + 带 ASCII 边界保护的 Aho-Corasick；
  3. `Δopacity ≡ 0.0` 单态稳态渲染 + `68:32⇄65:35` 舞台 + 3 阶字号与 PPT 扁平破锁；
  4. `--dual` 对称镜像 + `sanitizeTargetForChannel` 纯度防火墙 + 50% 省流门控 + `/en`/`/zh`/`/split` + 316 项自动化门禁。
- **重点借鉴（吸收 `Mimi` 与优秀开源项目精华）**：
  1. macOS 14.2+ `AudioHardwareCreateProcessTap` 免 BlackHole 采集与可选 SpeexDSP AEC；
  2. `NonactivatingPanel` + `NSScreenSaverWindowLevel` + `CanJoinAllSpaces | FullScreenAuxiliary` + `NSWorkspaceActiveSpaceDidChangeNotification` 跨 Space 全屏随行；
  3. 真点击穿透 + 悬停解锁胶囊、画布任意处拖拽、8 向屏幕坐标缩放、`280×54` 折叠迷你条；
  4. 无黑底纯透明 + 多层深色阴影/描边的沉浸模式与换行 `translateY` 微动画（保留 `0.0018ms` 吐字直写，不加会拖慢首字的防抖延迟）；
  5. 可插拔多模型抽象层与未来的薄壳 Sidecar 分发形态。

## 第六部分：优先吸收的工程动作清单（落地路线建议）

结合上述所有对比，建议以 **`阿里同声传译` (`v4.0.0`)** 为核心底座，按以下优先级推进演进：
1. **P0（浮窗交互质变）**：补全 macOS `NSPanel` 全屏 Space 跨区随行（`CanJoinAllSpaces | FullScreenAuxiliary` + `NSWorkspaceActiveSpaceDidChangeNotification`）、`Cmd/Ctrl+Shift+L` 真点击穿透 + 悬停解锁胶囊、全画布拖拽、`280×54` 折叠态、以及 Windows `1000ms` Topmost 心跳防 PPT 抢占。
2. **P0（音频零配置开箱）**：增加 macOS 14.2+ `AudioHardwareCreateProcessTap` 轻量辅助二进制直接内录（保留 `BlackHole 2ch` 回退），并按需增加双源可选 AEC 消回声。
3. **P1（阅读舒适与零延迟兼顾）**：引入 `Mimi` 沉浸无底多重阴影模式、`LiveCaptions-Translator` 的 `#pastLine` 对比度梯级弱化、以及仅作用于换行时的 `180ms` 平滑位移（保留现有 `0.0018ms` 吐字直写，不牺牲 `<380ms` 延迟）。
4. **P2（可扩展与防断线）**：抽离可插拔引擎接口（便于接入多模型与本地兜底）、加入 `/present` 局域网二维码扫码旁听，并在需要对外分发安装包时以“Tauri v2 薄壳 + Python Sidecar”形式封装，避免用 Rust 重写已有 Python 护城河。
